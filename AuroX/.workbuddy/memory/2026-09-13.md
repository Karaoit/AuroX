### 命名（与参数空间对称的无歧义缩写）
- `ActBase`（抽象基类，别名 `Act`；`Action` 为向后兼容别名）
- `ParamUpdateAction`（默认动作，别名 `ParameterUpdateAction`）
- `CustomAction`（数据型占位：承载未实现的 state/transition）、`FnAction`（lambda 动作）
- `ASpace` = `ActionSpace` 类型短别名；命名空间仍复用 `PSpace`（= AuroX::Space）。
- 宏对齐 `PARAM_REG`/`PARAM_BIND`：`ACT_TYPE(tag)`（一行生成 type()+clone()，须用于叶子类）、`ACT_REG(space, ...)` + `ACT_ADD(Type, ...)`。

### 关键设计决策
- 采纳草稿的 `ActionResult{Ok,Skipped,Disabled,Failed}` + `toString/toActionResult` 与 `ActionId/kInvalidActionId`，替代原来 void 返回，便于 UI 回执；新增 `ActOutcome`（id/name/result）逐动作记录。
- `apply()` 改为**非 const**（真实动作有状态，如轮次计数），`ActionSpace::applyAll/applyOne` 随之非 const。
- 保留并强化「优化器解耦」：更新源 `UpdateFn`（别名 `ParameterUpdateFn`）由编排器注入，ActionSpace 不 include 优化器。默认动作未接线时退化为 `-fallbackLr*gradient`，新增 `scale` 阻尼与 `useSource` 开关。
- 条件钩子两个：`shouldRun(space)`（用户运行时条件→Skipped）、`feasible(space)`（安全层准入→Skipped）；`enabled()`→Disabled。异常统一 try/catch 转 Failed，applyAll 遇 Failed 即停。
- 修掉草稿的坑：`add()` 对 `kInvalidActionId` 自动分配 id（草稿会静默丢弃动作）；`clear()` 复位为「仅默认动作」而非清空；补齐 `<cstdint>/<unordered_map>/<vector>` 等缺失头；动作类回到 `AuroX::Space` 命名空间内（草稿漏在命名空间外）。
- 新增能力：`emplace<T>(args...)` 就地构造、`addFn()` lambda 动作、`remove/removeById`、`get/getById/at/names`、`nextId()`、类型注册表 `registerActionType()`（让自定义动作也能 JSON 往返，工厂未知类型回退 ParamUpdateAction）、`tryFromJson()`（可复用 ParameterSpace.ipp 的通用 `tryLoadJson<SpaceT>`）。
- 序列化形态：`{version, actions:[{type,name,id,enabled,config}]}`。
