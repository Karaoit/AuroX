1 · 设计语言：把「实体」一个一个数清楚

「如非必要，勿增实体」落到代码上只有两条可操作的判据：

判据 A（类型）：如果删掉这个类型，1.html 里有没有任何一帧画不出来？——没有，就不该存在。
判据 B（字段）：如果删掉这个字段，有没有哪一行代码必须改成别的东西才能表达？——没有，就不该存在。

我按这两条把你给的 Action 与 1.html 的九帧逐一对齐，结论是：

3 · Action 结构体：你给的 5 个字段 + 唯一必需的第 6 个

// 执行函数：无参。需要什么就在闭包里捕获什么 —— 这是「外部函数可直接复用」的关键
using RunFn = std::function<void()>;

// 预测函数：入参是「假设状态」，返回「推演出的下一步状态」
using NxtFn = std::function<Vec(const Vec&)>;

// ─────────────────────────────────────────────────────────────
//  Action —— 基础结构体：纯数据，无继承、无虚函数、可聚合初始化
// ─────────────────────────────────────────────────────────────
struct Action {
    Str      name;        // ① 实例名（唯一身份）        ← 你给的
    Str      type;        // ② 类别名（同族动作共用）    ← 你给的
    uint64_t hash = 0;    // ③ 全局唯一 hash（快速查找）  ← 你给的
    RunFn    run;         // ④ 执行函数（可为外部函数的包装）← 你给的
    std::vector<Condition> conditions;   // ⑤ 条件向量            ← 你给的

    NxtFn    nxt;         // ⑥ 结束状态预测             ★ 唯一必需新增

    // 三个派生判断，避免调用方到处写 if
    bool can (const Vec& x) const { for (auto& c : conditions) if (!c.test(x)) return false; return true; }
    Vec  next(const Vec& x) const { return nxt ? nxt(x) : x; }   // 空 = 状态不变
    void exec()           const { if (run) run(); }
};
using Act = Action;   // 手感别名（命名约定：长名配短别名）

代码 1 · Action 结构体。前 5 个字段原样来自你的设计，第 6 个是唯一新增

3.1 为什么第 6 个字段「非加不可」

它的必要性只在两处体现，但这两处各自都是 1.html 的骨干：

用途没有它时会发生什么1.html 里的位置
前向推演
（plan 要离线在假设状态上走）		搜索无法知道「走这一步会到哪」，只能执行才知道——而规划必须在执行之前完成。整个 plan() 会退化成「人工排好顺序」。01 帧「逐层展开 18 个状态节点」
02 帧「回溯成链」
判定状态异常「异常」这个词没有判定依据。必须有一个事先算出的预测值，才能与实测值比较出偏差。04 帧「预测 (2,2) 实测 (2,1)」
06 帧「换约束重搜」
换一种说法

你给的 conditions 回答的是「这一步能不能走」； 新增的 nxt 回答的是「走完这一步会到哪」。 一个管入口，一个管出口。只有入口没有出口，就只能单步执行，无法规划、也无法发现异常—— 而 1.html 展示的正是「规划 → 执行 → 校验 → 重规划」这个闭环。

3.2 type 与 name、hash 的分工

字段回答的问题用法约定
name「我是哪一个」同一空间内唯一。面向上层与日志，如 "go"、"cut"
type「我属于哪一族」同族共用，如 "move"、"tool"。用于按类别批量禁用（banType("move") 这类扩展的落点）
hash「怎么最快找到我」登记时自动补：hashOf(type + "/" + name)。用户通常不写它；写了就以写的为准。
为什么 hash 用「自动补 + 冲突即抛异常」，而不是让用户手填

手填唯一的数字，是让使用者去承担一件机器该做的事，且一定会出现复制粘贴导致的重号。 自动补的版本用 constexpr FNV-1a 在编译期算好（type + "/" + name 拼接保证跨类别不撞）， 零运行时开销；万一真撞了，登记时直接抛异常——绝不静默覆盖，因为静默覆盖会表现为「某个动作莫名执行了另一个动作的行为」， 是最难查的一类故障。

4 · 三个使用范式

4.1 范式一：外部已有函数 —— 一行包装

这是你提出的核心场景。因为 RunFn 是无参闭包，任何签名的外部函数都能在一行里被接上：

void moveCam(int a, int b);        // 移动镜头

Action go, zoom, sort;

// 把外部函数与它的实参一起「焊」进闭包
go.run   = [&]{ moveCam(2, 3); };          // ← 你给的写法
zoom.run = [&]{ zoomTo(1.5); };

4.2 范式二：同一族动作的多种执行函数

「以此类推多种执行函数」——每个动作各自持有自己的闭包，互不干扰，且共享同一套 type 与状态推演：

R.name = "R";  R.type = "move";
R.run  = [&]{ moveCam(+1, 0); };
R.nxt  = [](const Vec& x){ auto y = x; y[0] += 1;   return y; };

J.name = "J";  J.type = "move";
J.run  = [&]{ moveCam(+2, 0); };
J.nxt  = [](const Vec& x){ auto y = x; y[0] += 2;   return y; };
J.conditions = { {"y >= 1", [](const Vec& x){ return x[1] >= 1.0; }} };

4.3 范式三：条件向量 —— 与系统状态结合

Condition 是本次唯一需要新增说明的辅助结构，最小到两个字段：

struct Condition {
    Str desc;                             // 人读描述（1.html 动作行里那一列）
    std::function<bool(const Vec&)> ok;   // 判据；留空 = 恒真
    bool test(const Vec& x) const { return !ok || ok(x); }
};
语义写法
恒真（1.html 的「总是」）{ "总是", {} } —— 或者干脆不往 conditions 里放这一条
依赖状态{ "x <= 3", [](const Vec& x){ return x[0] <= 3.0; } }
依赖外部量{ "gain > 0", [&](const Vec&){ return gain_ > 0.0; } } —— 按引用捕获，判据可读实时量
多条a.conditions = { c1, c2 }; // 全部为真才允许执行（AND）
为什么是「全部为真」而不是「任一为真」

安全语义默认从严：条件集合是「放行所需的全部前提」，任一不满足就不执行。 需要「或」时，把它写进同一条条件内部（a || b），而不是让向量去猜。这样向量只有一种读法，不需要任何额外字段去标记「这是 AND 还是 OR」。

5 · 完整骨架代码（header-only）

这就是动作层的全部。唯一依赖是标准库——不 include 参数空间、不 include 状态 / 观测空间、不 include 优化器、不 include 硬件。

// =====================================================================
//  ASpace.hpp —— 动作层最小内核（header-only，约 120 行）
//  设计语言：如非必要，勿增实体。  4 类型 / 0 宏 / 1 头文件。
// =====================================================================
#pragma once
#include <cstdint>
#include <functional>
#include <string>
#include <string_view>
#include <unordered_map>
#include <unordered_set>
#include <vector>
#include <stdexcept>

namespace AS {

using Str = std::string;
using Vec = std::vector<double>;          // 中性状态向量：装什么由用户决定

// ── 0. 编译期 hash：全局唯一键，零运行时开销 ─────────────────────
inline constexpr uint64_t hashOf(std::string_view s) {
    uint64_t h = 1469598103934665603ULL;                     // FNV-1a 64
    for (char c : s) { h ^= uint64_t((unsigned char)c); h *= 1099511628211ULL; }
    return h;
}

// ── 1. Condition —— 一条判据（desc 供展示，ok 供判定）────────────
struct Condition {
    Str desc;
    std::function<bool(const Vec&)> ok;
    bool test(const Vec& x) const { return !ok || ok(x); }
};

// ── 2. Action —— 基础结构体（纯数据）───────────────────────────
using RunFn = std::function<void()>;
using NxtFn = std::function<Vec(const Vec&)>;

struct Action {
    Str      name;
    Str      type;
    uint64_t hash = 0;
    RunFn    run;
    std::vector<Condition> conditions;
    NxtFn    nxt;                                  // ★ 唯一必需新增

    bool can (const Vec& x) const {
        for (auto& c : conditions) if (!c.test(x)) return false;
        return true;
    }
    Vec  next(const Vec& x) const { return nxt ? nxt(x) : x; }
    void exec()           const { if (run) run(); }
};
using Act = Action;

// ── 3. Chain —— 选链产物（链 = 线性边表）───────────────────────
struct Chain {
    bool ok = false;
    Str  why;
    std::vector<uint64_t> acts;                    // 动作 hash 序列（链）
    std::vector<std::pair<int,int>> edges;           // 仅 asGraph=true 时填（图）
};

// ── 4. ASpace —— 动作空间 ──────────────────────────────────────
class ASpace {
public:
    // 登记：把派生类里的 Action 成员一次交给空间（不是逐个 add）
    template <class... A> void reg(A&... as) { (reg_(as), ...); }
    void reg_(Action& a);

    // 状态
    const Vec& cur() const       { return cur_; }
    void       cur(const Vec& s) { cur_ = s; }

    // 查找
    Action* get(uint64_t h);
    Action* get(const Str& nm);
    std::size_t size() const { return byHash_.size(); }

    // 执行：条件全过才执行，随后状态按预测推进
    bool run(uint64_t h);
    bool run(const Str& nm);

    // 禁用集
    void ban  (uint64_t h)       { ban_.insert(h); }
    void unban(uint64_t h)       { ban_.erase(h);  }
    bool banned(uint64_t h) const { return ban_.count(h) > 0; }

    // 选链（唯一扩展点）与重规划
    virtual Chain plan(const Vec& goal, int maxDep = 8, double eps = 1e-6, bool asGraph = false);

    // 重规划 == 换一组禁用，重跑同一次 plan
    Chain replan(const Vec& goal, uint64_t culprit, int maxDep = 8, double eps = 1e-6) {
        ban(culprit);
        return plan(goal, maxDep, eps);
    }

private:
    Vec                            cur_;      // 当前状态（由用户写入）
    std::unordered_map<uint64_t, Action*> byHash_;   // hash → 动作（零拷贝）
    std::vector<uint64_t>          order_;    // 声明顺序（结果可复现）
    std::unordered_set<uint64_t>   ban_;      // 禁用集
};

inline double dist(const Vec& a, const Vec& b) {
    double d = 0;
    for (std::size_t i = 0; i < a.size() && i < b.size(); ++i) { double t = a[i] - b[i]; d += t * t; }
    return d;
}

} // namespace AS

5.1 四个成员函数的实现

// ── 登记：自动补 hash；冲突直接抛，绝不静默覆盖 ──────────────────
inline void ASpace::reg_(Action& a) {
    if (a.hash == 0) a.hash = hashOf(a.type + "/" + a.name);
    auto r = byHash_.emplace(a.hash, &a);
    if (!r.second && r.first->second != &a)
        throw std::runtime_error("ASpace: hash 冲突 -> " + a.type + "/" + a.name);
    order_.push_back(a.hash);                     // 保持声明顺序
}

// ── 查找 ────────────────────────────────────────────────────────
inline Action* ASpace::get(uint64_t h) {
    auto it = byHash_.find(h);
    return it == byHash_.end() ? nullptr : it->second;
}
inline Action* ASpace::get(const Str& nm) {          // 线性扫描，n 个动作足够快
    for (auto& kv : byHash_) if (kv.second->name == nm) return kv.second;
    return nullptr;
}

// ── 执行：条件门 → 执行体 → 状态推进 ────────────────────────────
inline bool ASpace::run(uint64_t h) {
    if (ban_.count(h))          return false;   // 已禁用
    Action* a = get(h);
    if (!a)                     return false;   // 不存在
    if (!a->can(cur_))          return false;   // 条件未全满足
    a->exec();                                    // 执行（闭包内捕获一切）
    cur_ = a->next(cur_);                         // 状态按预测推进
    return true;
}
inline bool ASpace::run(const Str& nm) {
    Action* a = get(nm);
    return a ? run(a->hash) : false;
}

代码 4 · reg_ / get / run。没有第 8 个注入位，也就没有「忘接线就静默失效」的空间

5.2 plan()：唯一的算法部分，也是唯一可覆写的函数

inline Chain ASpace::plan(const Vec& goal, int maxDep, double eps, bool asGraph) {
    Chain out;

    struct Node { Vec x; int par; uint64_t h; };
    std::vector<Node> seen{ { cur_, -1, 0 } };             // 起点 = 用户给的当前状态
    if (dist(seen[0].x, goal) <= eps) { out.ok = true; return out; }

    std::vector<int> layer{ 0 };
    for (int d = 0; d < maxDep && !layer.empty(); ++d) {
        std::vector<int> next;

        for (int i : layer)
        for (uint64_t h : order_) {
            if (ban_.count(h))              continue;      // ① 禁用集
            Action* a = byHash_.at(h);
            if (!a->can(seen[i].x))        continue;      // ② 条件不满足 → 不成边
            Vec nx = a->next(seen[i].x);                    // ③ 预测下一步

            bool dup = false;
            for (const Node& n : seen) if (dist(n.x, nx) <= eps) { dup = true; break; }
            if (dup) continue;                              // ④ 去重

            seen.push_back({ nx, i, h });
            int k = (int)seen.size() - 1;

            if (dist(nx, goal) <= eps) {                    // ⑤ 命中 → 回溯成链
                std::vector<uint64_t> r;
                for (int p = k; p > 0; p = seen[p].par) r.push_back(seen[p].h);
                out.acts.assign(r.rbegin(), r.rend());
                out.ok = true;
                return out;
            }
            next.push_back(k);
        }
        layer = next;
    }

    if (asGraph) {                                        // 没命中也要交付「图」
        for (std::size_t i = 0; i < seen.size(); ++i)
            if (seen[i].par >= 0) out.edges.push_back({ seen[i].par, (int)i });
    }
    out.why = "unreachable within depth " + std::to_string(maxDep);
    return out;
}

5.3 调用的完整闭环（对应 1.html 的 03 → 08）

Vec goal{ 4.0, 2.0 };
sp.cur({ 0.0, 0.0 });

for (int round = 0; round < 8; ++round) {

    Chain ch = sp.plan(goal, 8, 1e-6, true);          // 01 / 02
    if (!ch.ok) break;                                // 不可达 → 交给上层

    bool broken = false;

    for (uint64_t h : ch.acts) {                        // 03 逐步执行
        Action* a    = sp.get(h);
        Vec     pred = a->next(sp.cur());                 // 事先算出的预测值

        if (!sp.run(h)) { sp.ban(h); broken = true; break; }   // 条件不过 → 封锁

        Vec real = sense();                               // 实测（用户自己接）
        if (dist(real, pred) > 1e-6) {                   // 04 状态异常
            sp.ban(h);                                    // 05 封锁肇事动作
            sp.cur(real);                                 // 以实测为准
            broken = true;
            break;                                        // 06 / 07 回到循环开头重新 plan
        }
        sp.cur(real);                                     // 校验通过，对齐实测
    }

    if (!broken) break;                               // 08 到达目标
}

// 外部已有函数

struct Nav : ASpace {
    Action R, U, D, J;

    Nav() {
        R.name="R"; R.type="move";
        R.run = [&]{ moveCam(+1, 0); };
        R.nxt = [](const Vec& x){ auto y=x; y[0]+=1;       return y; };

        U.name="U"; U.type="move";
        U.run = [&]{ moveCam(0, +1); };
        U.nxt = [](const Vec& x){ auto y=x; y[1]+=1;       return y; };

        D.name="D"; D.type="move";
        D.run = [&]{ moveCam(+1, +1); };
        D.nxt = [](const Vec& x){ auto y=x; y[0]+=1; y[1]+=1; return y; };

        J.name="J"; J.type="move";
        J.run = [&]{ moveCam(+2, 0); };
        J.nxt = [](const Vec& x){ auto y=x; y[0]+=2;       return y; };

        // 条件向量：与「系统状态」结合，决定这一步能否走
        D.conditions = { { "x <= 3", [](const Vec& x){ return x[0] <= 3.0; } } };
        J.conditions = { { "y >= 1", [](const Vec& x){ return x[1] >= 1.0; } } };

        reg(R, U, D, J);
    }
};

int main() {
    Nav sp;
    sp.cur({ 0.0, 0.0 });                       // 当前状态

    Chain ch = sp.plan({ 4.0, 2.0 }, 8, 1e-6, true);
    // ch.ok  = true
    // ch.acts= { hash("move/D"), hash("move/D"), hash("move/J") }   ← 这就是「链」
    // ch.edges 非空（asGraph=true）                                  ← 这就是「图」

    for (uint64_t h : ch.acts) sp.run(h);          // 顺序执行，逐步反馈
}

6.3 档 2 · 高级（状态异常的 DAG 重规划）

「状态异常」的定义这次落在一个可以被直接读出来的地方：事先用 nxt 算出的预测值，与执行后的实测值之间的偏差。

// 闭环：搜索 → 执行 → 校验 → （异常就）封锁 → 重新搜索
Vec goal{ 4.0, 2.0 };

for (int round = 0; round < 8; ++round) {
    Chain ch = sp.plan(goal, 8, 1e-6, true);
    if (!ch.ok) break;

    bool broken = false;
    for (uint64_t h : ch.acts) {
        Action* a    = sp.get(h);
        Vec     pred = a->next(sp.cur());                     // 预测

        if (!sp.run(h)) { sp.ban(h); broken=true; break; }  // 条件不过 → 封锁

        Vec real = sense();                                   // 实测
        if (dist(real, pred) > 1e-6) {                   // 状态异常
            sp.ban(h);                                        // 封锁肇事动作
            sp.cur(real);                                     // 以实测为准
            broken = true;  break;                        // 回去重新 plan
        }
        sp.cur(real);
    }
    if (!broken) break;
}

异常被哪一行捕捉响应
条件当时不满足plan() 里 a->can() 为假 → 边不生成；执行期 run() 返回 false搜索绕开 / ban + 重规划
实测 ≠ 预测（模型不准）dist(real, pred) > epsban + 重规划
