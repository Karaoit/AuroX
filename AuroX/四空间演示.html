StateSpace —— 当前状态
唯一数据源：每个值只在 State::value 一处；动态访问与强类型字段命中同一份数据，不需要任何 sync 函数。 vec() 只输出 vectorized=true 的状态，按注册顺序排列；layout() 给出每个状态在 vec() 里的起始偏移。

    参数是配置 / 优化变量，会改变「动作怎么执行」，但不等于系统当前状态。写入没有旁路（raw() 只返回 const 指针）；

ActionSpace —— 动作与执行（规划见 Planner）

    动作层只认识中性的 Vec：参数/状态用闭包捕获，不持有当前状态、不含搜索——规划在 AuroX::Planner。
    Planner::bfs() 失败统一走 Chain{ok=false, why=...}；run() 只执行、不推演也不推进状态，true 不代表设备执行成功。

ObservationSpace —— 外部观测（已实现）

    有限维外部观测的入口：接收 → 严格校验 → 最近 N 条短缓存 → 稳定拼接为 Vec。它不是传感器驱动、不是控制器、不是状态估计器，也不会自动写 StateSpace。
  


  

    

      
职责边界

      
    
        
  • 注册通道，固定每样本维度与 historySize（条数，不是秒数）；
    • 
        
  • 标量 / 定长 Vec / 类别（one-hot）三类输入共用一个结构；
    • 
        
  • 可选时间戳 + validCount：区分「真实 0」与「未收到」、判断新鲜度。
    • 
      

      
与其它空间的边界

      

        
不做因为属于

        
编码器 / 归一化（MinMax/ZScore）外部训练 / 数据处理代码

        
状态估计 / 传感器融合任务相关的估计器（消费观测）

        
保存「当前状态」StateSpace

        
图像 / 点云 / 长期历史外部计算管线 / Memory

      

    

    

      
接口（已实现，非草案）

      
ObservationSpace obs;
obs.add("temperature", 1, 3);        // 3 条标量
obs.add("joint", 3, 2);              // 2 条、每条 3 维
obs.addCategory("mode", {"idle","run","fault"});
obs.freeze();                        // 锁定结构，ingest 仍可用

obs.ingest("temperature", 21.5);
obs.ingest("temperature", 22.0);
obs.ingest("joint", Vec{1,2,3});
obs.ingest("mode", Str{"run"});      // → one-hot [0,1,0]

auto b = obs.collect();              // 一致快照
// b.vector = [0,21.5,22.0, 0,0,0,1,2,3, 0,1,0]
// layout.validCount 区分真实样本与左侧补零

obs.ingest("joint", Vec{1,2,3}, 12.40);   // 可选时标
if (!obs.collect().layout[1].lastTimestamp) { /* 无时标/过期 → 外部安全逻辑 */ }
